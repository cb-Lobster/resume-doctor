# Resume Doctor Demo 2.0 — 简历诊断 Agent（可演示版）

面向「简历诊断 Agent」课程作业的可运行演示项目。**零第三方依赖**（只用 Python 标准库），
**内置 Python 运行时**（`runtime/python/python.exe`，Windows 64 位，无需安装任何东西），
双击 `启动.bat` 即可在教师机上跑起来。

> 仓库说明：本仓库**不含任何 API Key、不含任何真实简历数据**（`app/config.json`、`app/data/*.db`、
> `app/uploads/*` 都在 `.gitignore` 里）。首次运行前请按「一、三步启动 → 配置大模型」自备 Key；
> 不想配 Key 也能跑（自动降级到内置离线规则引擎）。
> 若本仓库未包含 `runtime/python/`，用系统 Python 3.8+ 执行 `python app/app.py --port 8765 --open` 即可，
> 或下载 Release 里的「零安装 zip」（内置运行时，双击即用）。

## 一、三步启动

1. 把整个 `resume-doctor-demo` 文件夹拷到教师机（放桌面即可，路径不要含中文以外的特殊符号）；
2. **双击 `启动.bat`**；
3. 浏览器自动打开 <http://127.0.0.1:8765>，看到顶部出现「引擎 deepseek-chat · 在线」或「离线规则引擎」即启动成功。

> 关闭：直接关掉黑色命令行窗口，服务即停止。
> 端口被占用时会自动顺延（8765 → 8766 → …），控制台会打印实际地址。
> `启动.bat` 与 `演示步骤.txt` 的编码：`启动.bat` 为 GBK（cmd 需要），其余文本文件为 UTF-8。

**配置大模型（可选）**：把 `app/config.example.json` 复制为 `app/config.json`，填入自己的 `api_key`
（申请：<https://platform.deepseek.com>）。也可以不改文件，用环境变量 `DEEPSEEK_API_KEY` 覆盖。
**没有 key 也能演示**——系统会自动降级到内置离线规则引擎，追问/依据/校准/看板全部照常工作。

## 二、演示主流程（约 6 分钟）

### 第 1 步｜① 诊断：一份"很差"的简历

在「① 诊断」页点示例 chip **`李萌（需改进）`**，JD 也点 **`云计算运维实习`** 示例，
然后点 **开始诊断**。页面顶部会走 9 个阶段的进度条（解析 → 结构 → 追问 → 评分 → 依据 → 改写 → 对比 → 落库）。

### 第 2 步｜澄清追问（功能 A 的一半）

**先问后评**：系统在出分之前先停住，弹出 3~5 个结构化追问，例如

- 「你做的 Zabbix 监控覆盖了多少台主机？」
- 「简历里没看到证书，是否已取得 CKA / RHCE？」

每题带快捷选项（如"50 台以上 / 20~50 台 / 10 台以内"），也可以自己填。
**这些答案会作为「用户确认事实」注入评分 prompt** —— 也就是说，Agent 承认自己看不出来，
先问清楚再打分，而不是凭空猜测扣分。点「开始评分」进入下一步。

> 演示对比：第二份简历 `张伟 v1` 结构完整，追问只有 1~2 条，直接出分。

### 第 3 步｜② 诊断报告：六维度 + 每条都有依据

报告页自上而下：

- **总分红环**（35 分 / 100）+ JD 匹配度标签（高度匹配 / 基本匹配 / 偏低）；
- **六维度雷达图**：JD 关键词匹配(25)、成果量化(20)、结构与重点(15)、
  表达质量 STAR(15)、硬性信息完整(15)、细节规范(10)，与 `kb/rubric.md` 完全一致；
- **六维度明细**，每个维度右侧都有「依据：维度 N · 名称 · X-Y 档 ▾」徽标，点开显示
  **该档位的原文条款**（引号括起）+ **`kb/rubric.md` 第 N 行** + **该维度检查要点原文**；
- **扣分点清单**，每条扣分同样挂依据；
- **改写建议**：把空泛描述改成可量化的 STAR 句式，右侧给出改后文案（可直接复制）。

这里的依据**不是模型编的**：`rd/trace.py` 先解析 rubric 的档位表，再用模型给的分数
**反查**对应的档位区间，所以引用的条款一定真实存在于知识库文件中。

### 第 4 步｜③ 版本库 + v2 对比

点 `张伟 v2` 再诊断一次，报告页的「版本对比」会显示
**35 → 85（+50）**、六维度逐项升降，并指出"哪几条建议被落实了"。

### 第 5 步｜④ 人工校准：Agent 到底准不准

进入「④ 人工校准」，选一条版本，填写**你自己的 HR 视角评分**（总分 + 六维度）。
留空时输入框会 ghost 提示「Agent 给了 35」，方便对照但不预填，避免"自己跟自己比"。

保存后页面立刻算出：

- **MAE**（平均绝对误差）
- **±5 分命中率**
- **Pearson 相关系数**（样本 < 3 时显示"样本不足"，不硬编数字）
- **维度系统偏差**：哪个维度 Agent 长期偏高/偏低（|bias| > 2 且样本 ≥ 2 才标红）

> 演示时可以现场故意打一个和 Agent 差很多的分数，看指标实时变化。

### 第 6 步｜⑤ 采纳看板：建议到底有没有用

「⑤ 采纳看板」评估的不是"评分准不准"，而是**"建议值不值得听"**：

- **采纳率** = 被勾选"我已采纳"的扣分点 / 全部扣分点；
- **逐版本进度条**：v1 采纳 2/3（67%）、v2 采纳 0/3；
- **采纳 → 提分**：把相邻版本配对，算出"采纳后分数涨了多少"（v1→v2 **+50 分**）。

> 如果只想快速看效果，校准页和看板页右上角都有 **「一键载入演示数据」**，
> 一次性生成两条历史版本 + 人工分 + 采纳记录。

### 第 7 步｜⑥ 方案说明

一页讲清设计取舍：为什么「先问后评」、依据粒度为什么选「维度 + 扣分点」、
人工评分为什么收「总分 + 六维度」、离线兜底怎么保证演示不翻车。

## 三、三个可讲的设计点

| 设计点 | 问题 | 做法 |
| --- | --- | --- |
| **澄清追问** | 简历信息不全时模型会瞎猜、乱扣分 | 8 条确定性规则先扫描缺口（量化/结果/JD 缺口/技能/证书/到岗/联系方式/自我评价注水），按"预期提分"排序取前 5 条，答案回填为事实 |
| **依据溯源** | "为什么扣这 5 分"讲不清，评分不可信 | 解析 `kb/rubric.md` 的档位区间表，用分数反查档位，引用条款 + 行号；扣分点同样挂依据 |
| **人工校准 + 采纳看板** | 只有分数没有可信度；建议看着好但没验证 | MAE / ±5 命中率 / Pearson / 维度偏差；采纳率 + 采纳后提分，形成"建议是否有效"的闭环 |

## 五、常见问题

**Q：双击 `启动.bat` 闪一下就没了？**
控制台末尾有 `pause`，正常不会闪退。若真的闪退，说明 `runtime\python\python.exe` 被删了；
`启动.bat` 会自动尝试系统 `py -3` / `python`，仍失败会打印原因。
实在不行在项目根目录执行：`runtime\python\python.exe app\app.py --port 8765 --open`

**Q：页面打不开 / 一直转圈？**
看命令行窗口是否还在跑。若提示端口占用，直接访问控制台打印的顺延端口（如 8766）。
**不要用 `file://` 直接打开 `app/web/index.html`**，必须走服务地址。

**Q：没有网络能演示吗？**
能。断网或 key 失效时自动切离线规则引擎，顶部标签会显示「离线规则引擎」。
离线模式下：追问、依据溯源、报告、版本对比、校准、采纳看板**全部可用**；
差别是评分由确定性规则给出（关键词覆盖率、量化计数、动词/结果词密度），
改写建议走固定句式框架而非大模型生成。

**Q：数据存在哪？会上传吗？**
全部在本机 `app/data/doctor.db`（SQLite）。除了调用大模型 API 时发送简历文本外，不做任何外发。
重新演示前想清空数据：关掉服务，删掉 `app/data/doctor.db` 即可（下次启动自动重建）。

**Q：教师机是 32 位系统？**
内置运行时是 64 位。`启动.bat` 会自动回退到系统 Python 3.8+，功能不受影响。
